# 집중포화 (CROSSFIRE) 설계 문서 v0.1

> 발로란트 '체임버' 모티브의 뱀파이어 서바이벌류 트윈스틱 슈터. PC 브라우저 전용, 혼자 즐기는 개인 프로젝트.
> 이 문서는 Claude Code에 전달하는 구현 명세다. 마일스톤(9장)을 한 번에 하나씩만 구현시킨다.

---

## 1. 컨셉 요약

- 한 판 약 22분, 12라운드(라운드당 전투 90초 + 구매 페이즈).
- WASD로 이동, **마우스는 조준만** 담당, **발사는 전부 자동**.
- 전투 중에는 뱀서처럼 적이 떨어뜨리는 **XP(Experience Points, 경험치) 조각**으로 레벨업하고 스킬/패시브를 고른다.
- 라운드 사이에는 발로란트식 **구매 페이즈**에서 **크레딧**으로 총기 획득·등급 업·방어구·궁극기 충전을 산다.
- 차별점: 뱀서의 "물량에 파묻히기"를 "함정으로 묶고 정밀하게 솎아내기"로 뒤집는다.
- 고유 패시브 **집중포화**: 함정 감속 필드 안의 적은 모든 피격이 크리티컬이 된다.

## 2. 기술 스택과 원칙

- 순수 JavaScript(JS) + HTML5 Canvas. 번들러 없이 ES modules로 시작한다(필요해지면 Vite 도입).
- 배포: GitHub Pages(GitHub Actions로 자동 배포). 플레이는 링크를 열어서 한다.
- 대상: PC 브라우저(마우스+키보드). 모바일 미지원.

**불변 원칙 (어기면 나중에 밸런스 봇이 불가능해진다)**

1. **로직/렌더 분리**: `src/core/`는 `window`, `document`, `canvas`, `Date.now`, `Math.random`을 절대 쓰지 않는다. 순수 JS 모듈이어야 Node에서 그대로 돌아간다.
2. **고정 시간 스텝**: 로직은 항상 60Hz, `DT = 1/60`. 렌더러가 프레임마다 `step`을 필요한 횟수만큼 호출한다(누적기 방식).
3. **시드 RNG(Random Number Generator, 난수 생성기)**: `mulberry32(seed)` 하나를 state에 두고 모든 난수는 여기서 뽑는다. 같은 시드 + 같은 입력 = 같은 결과.
4. **데이터 주도**: 모든 수치는 `src/data/*.js`에 둔다. 코드에 매직 넘버 금지.
5. **UI 선택은 상태로 표현**: 레벨업/구매는 `state.pending`에 선택지를 올려두고, 외부(UI 또는 봇)가 `choose(state, index)`로 응답한다.

## 4. 코어 인터페이스

```js
const state = createGame(seed);          // 새 게임
step(state, input);                      // 1틱(1/60초) 진행
choose(state, index);                    // state.pending 에 대한 응답
state.events;                            // 매 틱 비워지는 이벤트 배열 (렌더/사운드용)
```

**input**

```js
{
  move: { x: -1|0|1, y: -1|0|1 },        // WASD
  aim:  { x, y },                        // 월드 좌표상의 조준점 (렌더러가 카메라로 변환해 넣음)
  keys: { c: bool, q: bool, e: bool, x: bool }   // 이번 틱에 눌림(엣지) 또는 유지(q)
}
```

**phase 상태 기계**

```
MENU → COMBAT ⇄ (LEVELUP 오버레이로 일시정지) → ROUND_END → BUY → COMBAT ... → VICTORY | DEFEAT
```

- LEVELUP 중에는 `step`이 시뮬레이션을 진행하지 않는다(`state.pending`이 있으면 no-op).
- BUY는 **시간 제한 없음**, 플레이어가 "다음 라운드"를 누르면 진행.
- 라운드 종료 시 남은 적은 소멸하고, 필드의 XP 조각과 크레딧은 자동 흡수된다.

## 5. 게임 규칙

### 5.1 월드와 조작

- 월드: 2000×2000 경계가 있는 아레나, 카메라가 플레이어를 따라간다.
- WASD 이동, 마우스 위치 = 조준 방향. **장착한 모든 총기가 각자 쿨다운마다 조준 방향으로 자동 발사**한다.
- 스킬 키: **C** 트레이드마크(함정), **Q** 헤드헌터(정조준 모드, 누르고 있는 동안), **E** 랑데뷰(순간이동), **X** 투르 드 포스(궁극기).
- 플레이어 시작 수치: HP(Hit Points, 체력) 100, 이동속도 220px/s, 자석 반경 90px.

### 5.2 한 판의 구조

| 항목 | 값 |
|---|---|
| 라운드 수 | 12 |
| 전투 시간 | 90초 / 라운드 |
| 엘리트 | 3, 6, 9라운드 |
| 최종 보스 | 12라운드 |
| 라운드 시작 시 HP 회복 | 최대 HP의 30% |

### 5.3 XP와 레벨업 (뱀서 구조 그대로)

- 적 처치 시 XP 조각 드롭, 플레이어가 자석 반경에 들어오면 흡수.
- **레벨업 보상 = 스킬 강화 / 패시브 / 총기 개조** 3지선다 (리롤 없음, 대신 상점의 카드 구매가 있음).

레벨업에 필요한 XP는 다음 식으로 계산한다. 기호부터 정의한다.

- `L`: 현재 레벨 (1부터 시작)
- `xpNeed(L)`: 레벨 `L`에서 `L+1`로 가는 데 필요한 XP
- `a, b, c`: 곡선 계수 (초기값 a=6, b=5, c=0.5, 튜닝 대상)

식: `xpNeed(L) = a + b·L + c·L²`

검산: `L=1`이면 6 + 5 + 0.5 = 11.5, `L=10`이면 6 + 50 + 50 = 106, `L=20`이면 6 + 100 + 200 = 306.

- 목표: 12라운드 종료 시 **레벨 18~22**. 스킬 4개(각 5레벨 = 20업)를 전부 찍기엔 모자라서 선택이 강제되도록 튜닝한다.
- 드롭량: 추격형 1, 돌격형 2, 원거리형 2, 엘리트 30.

### 5.4 크레딧 경제 (결정 사항)

**핵심 결정: XP와 크레딧의 쓰임새를 완전히 분리한다.**

| 재화 | 얻는 때 | 쓰는 때 | 사는 것 |
|---|---|---|---|
| **XP** | 전투 중 처치 | 전투 중 즉시(레벨업) | 스킬 강화, 패시브, 총기 개조 카드 |
| **크레딧** | 전투 중 처치 + 라운드 클리어 보너스 | 라운드 사이 구매 페이즈 | 총기 획득, 총기 등급 업, 방어구, 궁극기 충전, 카드 1장 |

- 총기의 **본체 성장(획득, 등급 업)은 오직 크레딧**, 스킬과 패시브는 오직 XP다. 그래서 "XP는 전투 중 즉흥 선택, 크레딧은 라운드 사이 계획 선택"이라는 리듬이 생긴다.
- **이월은 100%** 한다(원작의 손실 보너스, 연패 보너스는 도입하지 않는다). 모아뒀다 한 번에 비싼 총을 사는 전략이 가능하다.
- 상점은 **결정적(고정 목록)** + 무작위 카드 1칸으로 단순하게 간다.

**크레딧 수입 식** (기호 먼저):

- `R`: 라운드 번호 (1~12)
- `K`: 그 라운드의 처치 수
- `c̄`: 처치당 평균 크레딧 (추격형 10, 돌격형 15, 원거리형 20, 엘리트 150의 가중 평균, 대략 12)
- `B0`: 클리어 보너스 기본값 (200)
- `b1`: 라운드당 보너스 증가분 (30)
- `B(R)`: 클리어 보너스
- `I(R)`: 라운드 총 수입

유도: 클리어 보너스 `B(R) = B0 + b1·R`, 처치 수입은 `K·c̄`, 따라서 `I(R) = K·c̄ + B0 + b1·R`.

검산: `R=3`, `K=100`, `c̄=12`라면 `B(3) = 200 + 90 = 290`, 처치 수입 `100 × 12 = 1200`, 합계 `I(3) = 1490`.

**상점 목록 (구매 페이즈)**

| 칸 | 내용 | 초기 가격 |
|---|---|---|
| 총기 구매 | 미보유 총 (슬롯이 차 있으면 교체) | 셰리프 1500 / 밴달 2800 |
| 등급 업 | 보유 총의 다음 티어 | 티어2 1000 / 티어3 2200 |
| 방어구 | 라이트(실드 25) / 헤비(실드 50). 실드는 라운드를 넘어 유지, HP보다 먼저 피해를 흡수 | 400 / 800 |
| 궁극기 충전 | 궁극기 오브 +1 (최대 보유 수 제한) | 1500 |
| 카드 1장 | 레벨업 풀에서 무작위 카드 1장 즉시 획득 | 600 |

- 총기 슬롯은 **2개**(주무기, 보조). 두 총이 동시에 자동 발사한다. 클래식은 시작 시 보조 슬롯에 있고 교체 가능.
- 가격은 전부 `data/balance.js`에 두고 밸런스 봇으로 튜닝한다. 위 수치는 출발점일 뿐이다.

|---|---|---|---|---|

| 셰리프 | 단발 고위력 | 피해 40, 연사 1.2/s, 크리 확률 15% | 헤드헌터 Lv3 | 6발 연속 크리티컬이면 즉시 재장전 |

### 5.8 적

| 적 | 행동 | 초기 수치 (R=1 기준) |
|---|---|---|
| 추격형 | 플레이어에게 직진 | HP 20, 속도 90, 접촉 피해 8 |
| 돌격형 | 0.8초 예고선 후 직선 돌진 | HP 45, 속도 70(돌진 380), 피해 15 |
| 원거리형 | 거리 320 유지, 2초마다 투사체 | HP 25, 투사체 피해 10, 탄속 260 |
| 엘리트(3,6,9R) | 3방향 부채꼴 투사체 + 느린 추격 | HP 800 |
| 보스(12R) | 패턴 3단계 (MVP 이후 상세 설계) | HP 6000 |

**스폰 예산 방식**: 적마다 `cost`(추격 1, 돌격 3, 원거리 3)를 두고, 라운드마다 "초당 예산"을 소비하며 스폰한다. 예산 식은 다음과 같다.

- `R`: 라운드 번호
- `S0`: 1라운드 초당 예산 (초기 3)
- `g`: 라운드당 증가량 (초기 0.5)
- `S(R)`: 라운드 `R`의 초당 예산

유도: 1라운드는 `S0`, 이후 라운드마다 `g`씩 늘어나므로 `S(R) = S0 + g·(R − 1)`. 검산: `R=1`이면 3, `R=12`면 3 + 0.5 × 11 = 8.5.

**적 체력 스케일링**: `k`를 라운드당 체력 증가율(초기 0.15)이라 하면, 체력 배율 `h(R) = 1 + k·(R − 1)`, 적 HP = 기본 HP × `h(R)`. 검산: `R=12`면 `h = 1 + 0.15 × 11 = 2.65`.

- 라운드 구성 비율(초기): R1~2는 추격형만, R3부터 돌격형, R5부터 원거리형 혼합.
- 적이 화면 밖에서 스폰되고, 플레이어 주변 일정 반경 안에는 스폰하지 않는다.

### 5.9 승리/패배

- HP 0이면 DEFEAT. 12라운드 보스를 처치하면 VICTORY.
- 결과 화면에 라운드, 레벨, 처치 수, 최종 빌드를 표시한다.

## 6. 충돌과 성능

- 투사체 vs 적 충돌에 **공간 해시(셀 크기 64px)**를 사용한다. 동시 적 300~500개, 투사체 수백 개를 목표로 한다.
- 오브젝트 풀링(투사체, 조각, 이펙트)으로 GC(가비지 컬렉션) 스파이크를 줄인다.
- 렌더는 도형(원, 선, 삼각형)과 코드로 그린 이펙트만 사용한다. 외부 에셋 없음.

## 7. 렌더/UI

- 피격/처치/크리티컬은 이펙트와 화면 흔들림으로 구분하되, 설정에서 끌 수 있게 한다.

## 8. 헤드리스 시뮬레이터와 GitHub Actions

**sim/run.js** (Node)

```
node sim/run.js --seeds 300 --bot greedy --out report.json
```

- `createGame(seed)` → `step`을 최고속으로 반복. 렌더 없음.
- **greedy 봇**: 조준은 가장 가까운 적, 이동은 적 밀집 반대 방향 + 조각 쪽으로 가중, 선택은 우선순위 표(스킬 > 총기 개조 > 패시브)와 상점 우선순위 표를 따른다.
- 출력: 승률, 평균 생존 라운드, 라운드별 사망 분포, 카드/총기 픽률, 평균 레벨, 평균 크레딧 이월량, 평균 DPS(Damage Per Second, 초당 피해량).

**.github/workflows/balance.yml**

- 트리거: `workflow_dispatch` + `src/data/**` 변경 시.
- 단계: checkout → Node 설치 → `node sim/run.js ...` → 리포트를 artifact로 업로드.
- 목표 지표(초기): greedy 봇 승률 10~30%, 평균 생존 8~11라운드. 이 범위를 벗어나면 `data/balance.js`를 조정한다.

**.github/workflows/pages.yml**

- `actions/configure-pages` → `actions/upload-pages-artifact` → `actions/deploy-pages` 표준 구성.
- main 브랜치 푸시 시 자동 배포.

## 9. 구현 마일스톤 (한 번에 하나씩)

1. **M1 뼈대**: 폴더 구조, 고정 스텝 루프, 시드 RNG, 플레이어 이동 + 마우스 조준 + 클래식 자동 발사, 추격형 적 + 처치. 렌더는 도형만. `core`가 Node에서 import 가능한지 테스트로 확인.
2. **M2 성장 루프**: XP 조각, 레벨업 오버레이, 패시브 3종, 라운드 타이머와 라운드 전환.
3. **M3 크레딧과 상점**: 크레딧 드롭/수입, BUY 페이즈, 총기 구매·등급 업(셰리프, 밴달), 방어구.
4. **M4 스킬**: C → E → Q → X 순서로 구현. 감속 필드와 집중포화 패시브 포함.
5. **M5 적 다양화**: 돌격형, 원거리형, 엘리트, 스폰 예산 시스템.
6. **M6 진화와 분기**: 진화 조건 검사, 스킬 3레벨 분기 A/B.
7. **M7 시뮬레이터**: `sim/run.js` + greedy 봇 + 리포트. 첫 밸런스 패스.
8. **M8 Actions**: pages.yml, balance.yml.
9. **M9 보스와 마감**: 12라운드 보스, 결과 화면, 설정, 이펙트 다듬기.

각 마일스톤 종료 조건: ① 플레이 가능 ② `node --test tests/` 통과 ③ 이번 마일스톤에서 추가한 수치가 전부 `src/data/`에 있음.

## 10. MVP(Minimum Viable Product, 최소 기능 제품) 범위

M1~M5까지만 하면 "집중포화의 재미가 있는가"를 검증할 수 있다.

- 에이전트 1명(체임버), 총 3종(클래식, 셰리프, 밴달), 스킬 4개(분기는 각 1개씩만), 적 3종 + 엘리트 1종, 라운드 4개로 시작.
- 검증 질문: ① 트랩으로 묶고 처치하는 흐름이 자연스러운가 ② 구매 페이즈가 라운드 사이 리듬을 만드는가 ③ XP/크레딧 분리가 선택을 흥미롭게 하는가.

## 11. IP(Intellectual Property, 지식재산권) 메모

- 혼자 즐기는 비공개 프로젝트라면 발로란트 이름(체임버, 밴달 등)을 그대로 써도 부담이 적다.
- **공개 저장소나 공개 배포로 전환할 때는** 이름·스킬명·비주얼을 오마주 수준으로 바꾸고, 에셋은 직접 만든 도형/코드 드로잉만 사용한다. 이름은 `data/` 한 곳에만 두어 치환을 쉽게 한다.
